# Pilot inputs, overrides, and calculation updates

Issue #7 replaces durable calculated revision history with pilot-input persistence. The active planner stores one current input document per plan in its versioned v2 IndexedDB database, along with aircraft profiles. The document keeps literal editor text, including blank, incomplete, and invalid values, ordered checkpoints, selected profile values, override reasons, and explicit forecast choices. Leaving an input field saves the working copy without fetching external data, calculating, or adding a submission checkpoint. A failed local write remains visible until a later successful write.

**Update plan** is the primary action that submits pilot inputs. It is available only when locally required fields validate, and its handler validates again. The submitted inputs are durably checkpointed before airport or weather retrieval begins. Each plan retains at most its latest 20 explicit submissions. If the checkpoint write fails, the update stops before external retrieval. If retrieval or calculation fails after the write, the submitted inputs remain saved and the error remains visible until a complete update succeeds.

Airport responses, METAR and winds products, provenance evidence, and calculated navlog output are ephemeral. A successful update displays a result only for the exact submitted inputs and that attempt's fresh external context. A pilot edit immediately makes the displayed result unavailable as current. A failed attempt clears any prior successful result. Reopening a plan or reloading the page starts without a result and requires another successful **Update plan**.

A forecast choice is pilot input. Before calculation, the planner checks that the exact saved choice remains available and applicable in current forecast discovery. An unavailable choice blocks the update with an explanation; the application does not silently select a replacement. Departure airport identity and selected METAR station identity are independent pilot inputs and are never inferred from one another.

Cruise-TAS override values and reasons are pilot inputs and are included in working-copy saves and explicit submission checkpoints. The successful calculation carries their provenance in the current result. Saving edits does not create a durable result revision. The current planner has no separate weather-only refresh action; any future weather-only refresh or recalculation must not add an input submission checkpoint.

Plan and aircraft-profile import/export are out of scope for the pre-1.0 effort. Data remains in the current browser's local store; the Worker receives only the airport and weather lookup parameters needed for a calculation and does not receive or retain plan records.
